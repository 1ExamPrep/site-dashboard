# Site Dashboard

One admin for all your static sites: traffic and button clicks, products, Shopify
sync, GitHub deploys. Shopify-style sidebar, a site switcher top-right, and a
"Connect a site" form that gives each site a tracker key.

```
server/index.js    routes, auth, tracker endpoint, stats queries
server/views.js    every page's HTML
server/db.js       Postgres (Render) or SQLite (local); secrets encrypted at rest
server/shopify.js  Admin GraphQL: collection -> catalog (same rules as the site template)
server/github.js   commit files, trigger builds, read runs/commits
server/sync.js     product sync + weekly scheduler + orders pull
public/t.js        the tracker script sites load
public/app.*       dashboard UI
render.yaml        one-click Render blueprint (web service + Postgres)
```

## Deploy on Render (about 10 minutes)

1. Push this folder to a GitHub repo (private is fine).
2. Render → **New → Blueprint** → choose the repo. Render reads `render.yaml` and
   creates the web service and a Postgres database.
3. In the service → **Environment**, set:
   - `ADMIN_EMAIL` and `ADMIN_PASSWORD` (your sign-in; the password can be
     changed later by setting a new value and redeploying)
   - `BASE_URL` = the service URL Render gives you, e.g. `https://site-dashboard.onrender.com`
     (or your custom domain once you add one under Settings → Custom Domains)
4. Open the URL and sign in.

`APP_SECRET` is generated by the blueprint; it encrypts the Shopify/GitHub tokens
in the database, so keep it (changing it makes saved tokens unreadable).

## Connect a site

**Connect a site** → name, live URL, GitHub repo + token, Shopify domain + token
(+ collection). Everything can be filled in later under Settings.

- **GitHub token**: GitHub → Settings → Developer settings → Fine-grained tokens →
  repository access: just that repo → permissions *Contents: read & write* and
  *Actions: read & write*. The dashboard uses it to commit the catalog and
  trigger the site's `build.yml`.
- **Shopify token**: Shopify admin → Settings → Apps and sales channels →
  Develop apps → Create app → scopes `read_products` (and `read_orders` for the
  Orders page) → Install → copy the Admin API access token. One token can be
  reused by every site that sells from the same store.
- **Tracker**: Settings → Tracker shows the key and a one-line `<script>` snippet.
  Sites built from the electrician template only need `dashboardUrl` and
  `siteKey` in `site-config.json`, then `python3 build.py` and push. Any other
  site: paste the snippet before `</body>`; it records page views, Buy-now links
  (`/cart/…`), phone links, and anything with a `data-track="name"` attribute.

## What runs automatically

- **Weekly product sync** per site (day and hour set in Settings; hourly check).
  Pull collection → compare with last pull → if changed: update the Products
  page, commit `shared/catalog.js` + `store/products-full.json` to the site
  repo, trigger `build.yml`. Unchanged weeks do nothing. "Sync now" and
  "Force push catalog" are on Sync & Deploy.
- **Orders** are pulled with the sync and on demand (Refresh).

## Local run

```bash
npm install
ADMIN_EMAIL=you@example.com ADMIN_PASSWORD=secret APP_SECRET=anything npm run dev   # SQLite, scheduler off
```

## Data

Tracker events keep no cookies and no raw IP: a per-tab session id and a daily
hashed visitor id. Tokens are AES-256-GCM encrypted with `APP_SECRET`.
`/healthz` returns `{"ok":true}` for Render's health check.
